[4] ROOT CAUSE: WHY SALARY & EMPLOYEE FIELDS ARE STILL MISSING ON LIVE SERVER
--------------------------------------------------------------------------------
1. GET /api/v1/ems/auth/me currently queries core.employees by user_id and returns
   only `employeeCode` (e.g. "260831"), omitting:
     - employeeId (core.employees.id)
     - salary (core.employees.salary)
     - department (core.employees.department)
     - employmentType (core.employees.employment_type)
     - startDate (core.employees.start_date)
2. The mobile app cannot query /employees or /employees/me (both return HTTP 404).
3. When the mobile app falls back to GET /compensation:
   - Mobile only knows user.id (core.users.id) and user.employeeCode ("260831").
   - hr.compensation rows are keyed by employee_id (core.employees.id), so if
     GET /compensation does not embed employee.userId or employee.employeeCode
     (or the account has no row in hr.compensation / role is blocked from
     reading /compensation), no match can be found.

[5] RECOMMENDED BACKEND FIX (auth.service.ts -> GET /api/v1/ems/auth/me)
--------------------------------------------------------------------------------
In auth.service.ts where core.employees is already queried by user_id:

  SELECT
    id,
    employee_code,
    salary,
    department,
    employment_type,
    start_date
  FROM core.employees
  WHERE user_id = $1

Include these fields in the `user` object returned by GET /api/v1/ems/auth/me:
